## Problem
Every cross-repo capability assumes `flow.repo_name` and `flow.related_repos` are already declared. A project configured before cross-repo existed has neither, and nothing tells it so: `--add` skips the footprint question when `related_repos` is absent, `/flow:init` is a bootstrap step an existing repo already ran, and 1.25's validator delivers a hard stop (`flow.repo_name is not declared`) that routes nowhere. 1.29 ships the detection — `undeclared: <name>` and `undeclared-self:` — with its Out clause handing the disposition here. Nothing consumes it yet.

Shipped means: a repo that predates cross-repo is told what its config is missing, at the moments it matters, and is offered the fix.

## Value
As an engineer on a project that existed before cross-repo did I want flow to notice the missing config and offer to write it, so adopting the feature does not require me to already know its schema.

## Scope
**In:** consumers of 1.29's `undeclared:`/`undeclared-self:` report, all **confirm-first**. `/flow:lint` reports both and offers to write the entries, **gated behind `--fix`** per `commands/lint.md`'s standing read-only rule. `/flow:run --add` offers to bootstrap `related_repos` when the human **names** a repo the config does not declare — the offer is a response to their utterance, never a question flow raises on its own. `/flow:init --adopt` offers the block to a config that has none, leaving existing keys untouched. `flow-session-brief.sh` gains a **lowest-tier** nudge toward `/flow:lint` when `.flow/config.yml` declares `related_repos` but no `repo_name`. 1.25's hard-stop message is re-pointed at `/flow:init --adopt`.

**Out:** detecting anything (1.29 owns `undeclared:`). Writing config without confirmation. Any board read from the session brief. Authoring slices, scaffolding siblings, or the tag mirror — all 1.28's.

## Acceptance criteria
- [ ] `/flow:lint` reports every `undeclared:` name and `undeclared-self:` that 1.29 emits, and **writes nothing without `--fix`** — proven by a scratch run asserting the report appears and `.flow/config.yml` is byte-identical afterwards. `commands/lint.md` line 238 makes read-only-by-default a standing rule; an audit that edited config would break it.
- [ ] `/flow:lint --fix` writes the `related_repos` entries only on confirmation — proven by a scratch run declined then accepted, asserting the config is unchanged then correct.
- [ ] Both branches are exercised offline — the `undeclared:` case via 1.29's `--tags` input, the `undeclared-self:` case via a config carrying `related_repos` and no `repo_name` — proven by one scratch run each, so neither needs a live board.
- [ ] `--add` offers to bootstrap `related_repos` **only when the human names an undeclared repo**, and a run where they name none stays silent — proven by two scratch runs in the same `related_repos`-less repo, asserting the offer on the first and 1.28's no-new-question behavior on the second. The trigger is their utterance, not the config state; otherwise this contradicts 1.28's silence criterion.
- [ ] Declining the bootstrap still produces a valid single-repo spec — proven by asserting `flow-preflight.sh repos` is clean on the written file.
- [ ] `/flow:init --adopt` offers the block to a `.flow/config.yml` that lacks one and leaves every existing key byte-identical — proven by a scratch run against a config carrying only `lifecycle_authority`, diffing the untouched keys.
- [ ] The session brief nudges toward `/flow:lint` when `.flow/config.yml` declares `related_repos` but no `repo_name` — proven by a `hooks.test.sh` case in the existing `brief_for` form.
- [ ] It is the **lowest** ladder tier: any higher tier (open deferral, in progress, unshipped, board) wins and the nudge does not print — proven by a harness case with both conditions true, asserting exactly one line and that it is the higher tier's. 1.19's ladder is "highest true tier wins and only one ever prints".
- [ ] It costs one read of one file and nothing scales with backlog size — proven by inspection: the check greps `.flow/config.yml` only, invokes no preflight subcommand, and never scans the spec tree. The brief runs at every session start in every project, and `flow-session-brief.sh`'s own comment commits to nothing scaling with backlog size.
- [ ] A repo with no `related_repos` produces the brief output the harness already asserts literally — proven by an existing-form case, so the nudge is invisible to every project that has not adopted cross-repo.
- [ ] 1.25's `flow.repo_name is not declared` message names `/flow:init --adopt` — proven by a `hooks.test.sh` case asserting the emitted text, not by inspection: this edits a string in `flow-preflight.sh`, and root CLAUDE.md requires a harness case for hook changes.
- [ ] Every documentation surface is updated in the same change — `commands/lint.md`'s `--fix` row, `commands/init.md`'s `--adopt` section, `skills/run/reference/add.md`, `hooks/CLAUDE.md` (the new brief tier), and `docs/guide.md` §3 — proven by `grep -l 'related_repos'` over those five paths as operands.

## Decisions
- 2026-09-30 — **The brief fires on the config gap, not on a spec naming an undeclared repo.** The original amendment chose the latter, and its pre-build review showed the toolkit forbids that state: `cmd_repos` errors on an undeclared name and `flow-spec-guard.sh` exits 2, so such a spec cannot normally be saved — it arrives only by pull or hand-edit. `related_repos` set with `repo_name` missing is the opposite: genuinely reachable (no guard touches config), exactly the "configuration is missing" case, and detectable with one grep of one small file rather than a tree scan at every session start.
- 2026-09-30 — **Lowest tier, so the ladder still prints one line.** 1.19 ratified "highest true tier wins and only one ever prints"; a setup gap is the least urgent thing the brief can say, and sitting at the bottom also means the check is never reached when a higher tier already fired — which is how it stays free.
- 2026-09-30 — **The `--add` offer responds to the human, never to the config.** 1.28 asserts `--add` asks no footprint question in a repo without `related_repos`. Triggering on config state would contradict it. The trigger is the human naming a repo flow does not know.
- 2026-09-30 — **`/flow:lint` writes only behind `--fix`.** `commands/lint.md`: "Read-only by default — never modify files without `--fix`…". Adoption is no reason to carve an exception into an audit command; the report comes free, the write is asked for.
- 2026-09-30 — **Split from 1.28 at the amendment line.** Authoring and retrofit have different triggers, different mechanisms and different surfaces, and 1.28's own "Shipped means" never covered retrofit. This half needs only 1.29 (DONE), so it ships independently, and it carries both hook edits — and the `hooks.test.sh` obligations that come with them — which authoring does not need at all.

## Verification / evidence
Scratch runs per surface, all offline: the `undeclared:` branch via 1.29's `--tags` input, `undeclared-self:` via a config with no `repo_name`. Hook changes (the brief tier, the 1.25 message) carry `hooks.test.sh` cases per root CLAUDE.md; `bash hooks/hooks.test.sh` green is the gate.

**Coordination, not dependency:** 1.28 edits `commands/lint.md`, `commands/init.md` and `skills/run/reference/add.md` in the same regions. Intended order: 1.28 first (it owns the authoring text these sections wrap around), then this.
