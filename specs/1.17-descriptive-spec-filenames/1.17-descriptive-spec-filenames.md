## Problem
`specs/1.16.md` names nothing. In a file tree, an editor tab, a `git log --stat`, or a
PR's changed-files list, every spec is an opaque number — you must open it or cross-
reference the index to know what it is. The index already carries a free-text Title;
the filesystem never sees it. In ado mode a real story title sits on the card and never
reaches disk. Shipped = a spec's filename says what it is, in both shapes, without
breaking any existing bare-id spec anywhere.

## Value
As an engineer scanning a repo or a diff, I want each spec file's name to state what it
covers, so I can navigate the backlog without opening files or consulting the index.

## Scope
**In:** stem form `<id>-<slug>` for flat, orchestrator, and task files; guard accepts both
forms; one shared id→path resolver; slug inference (Title / `System.Title`);
`flow.spec_filename` knob; opt-in `/flow:lint --rename`; docs.
**Out:** automatic renaming (opt-in only); slugs in commit tags (`[<id>]` stays bare —
`/flow:ship` derives releases from it); changing the index entry format (already has Title).

## Acceptance criteria
- [ ] `specs/<id>-<slug>.md` with front-matter `id: <id>` passes the spec guard; a genuine
      id/stem mismatch still blocks — proven by `hooks.test.sh` cases both ways
- [ ] Dir form `specs/<id>-<slug>/` holds `<id>-<slug>.md` + `<id>-<slug>.T<n>-<ctx>.md`;
      the task-file local-AC nudge still fires on the slugged task stem — `hooks.test.sh`
- [ ] `flow-preflight.sh spec-path <id>` resolves all 8 cases (flat|dir × plain|slugged ×
      active|archive), exits non-zero on not-found and on ambiguity (two slugged matches for
      one id) — `hooks.test.sh`
- [ ] `to_resolves` + `cmd_resolved` call `spec-path`; no inline path lookup remains
- [ ] Deferral `DONE`-gate matches flat ids (`642103`), not just dotted — regression case
- [ ] `.flow/config.yml` `flow.spec_filename: id-slug|id` (default `id-slug`) selects the form
      new specs are authored in; hooks read no knob
- [ ] `/flow:lint --rename [<id>|--all]` git-mv's specs to slugged names and rewrites index
      links, confirm-first, never unprompted; an already-slugged repo is a no-op
- [ ] Self-migration: `/flow:lint --rename 1.17` renames this spec's own dir + 5 task files
      and the index link; `hooks.test.sh` green after
- [ ] README, `docs/guide.md`, `docs/how-it-works.md`, root + `hooks/CLAUDE.md` state the
      filename form and the knob

## Decisions
- 2026-07-29 — Slug on **every** stem (dir, orchestrator, task) rather than only the dir,
  keeping 1.6's rule that a spec dir is named for its orchestrator's stem.
- 2026-07-29 — Identity is the front-matter `id:`, never parsed out of the filename, so ids
  containing `-` (`BL-12`) stay unambiguous; the guard validates the stem *against* `id:`.
- 2026-07-29 — Config knob accepted despite CLAUDE.md's "no knobs until a second use":
  multi-project use means some repos want bare ids. Confined to `.flow/config.yml`
  (prompt-side); hooks accept both forms unconditionally so they gain no parsing or latency.
- 2026-07-29 — Slug caps: 40 chars for a spec, 20 for a task suffix, truncated at a word
  boundary — bounds total path length against Windows' 260-char limit.

## Verification / evidence
