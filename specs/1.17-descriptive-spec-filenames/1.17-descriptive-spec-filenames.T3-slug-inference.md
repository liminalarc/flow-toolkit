## Goal
Teach the authoring path to produce slugged names, and give a project one switch to opt out.

**Slugify rule** (stated once, in `skills/run/reference/authoring.md`, cited elsewhere):
lowercase; strip anything not `[a-z0-9]` to `-`; collapse runs; trim leading/trailing `-`;
truncate at a **word boundary** to **40 chars** for a spec slug, **20** for a task suffix.
Empty result (title was all punctuation) ⇒ fall back to the bare id.

**Source of the text:** local ⇒ the index entry's Title (already authored, so "inferred"
costs nothing); ado ⇒ the work item's `System.Title`. Task suffix ⇒ the task file's own
`title:`, not the parent's — a task carries the story name via its `<id>-<slug>` prefix
plus its own context.

**The knob:** `.flow/config.yml` → `flow.spec_filename: id-slug | id`, default `id-slug`.
Prompt-side only — it selects the form new specs are *authored* in. Hooks read no knob and
accept both forms unconditionally (T1), so no bash YAML parsing and no added hook latency.

Wire it into: `authoring.md` (both templates + the rule), `add.md` (index line + file
creation), `implement.md` (the detail file it writes at sign-off), `commands/init.md`
(scaffold the key with its default and document it).

## Done when
- [ ] The slugify rule + both caps are stated in exactly one place and cited, not restated
- [ ] `authoring.md` templates show `<id>-<slug>.md` and `<id>-<slug>/<id>-<slug>.T<n>-<ctx>.md`,
      noting the bare form stays valid
- [ ] `add.md` derives the slug from the Title and links the index entry at the real path
- [ ] `implement.md`'s sign-off write uses the resolved form
- [ ] `init.md` scaffolds `flow.spec_filename` with its default and explains `id`
- [ ] `flow.spec_filename: id` yields bare filenames; absent config behaves as `id-slug`
- [ ] Root `CLAUDE.md` Spec Status / Project Structure text stays accurate (full docs = T5)

## Notes
`.flow/config.yml` is the prompt-side backend config; `.flow-toolkit.json` is the hook-side
one. This knob belongs in the former — nothing in bash consumes it.
