## Goal
Route each declared scenario to whatever can actually run it, order the build outside-in, and let the three agents that currently guess the AC-to-proof mapping read it instead.

**Routing, in `implement.md`'s done-step.** One rule: `by: ux-validator` dispatches `flow-ux-validator` (serial, one per lens, exactly as the 1.15 gate does today); any other `by:` runs that command and reports pass/fail. The existing `validate:` block is read as a `by: ux-validator` scenario, so 1.14–1.16 behavior is unchanged and nothing about the rubric, drift check, or `NOT APPLICABLE` handling moves. No block and no `validate:` ⇒ pure no-op.

**Outside-in ordering, in `implement.md` section 3.** Before the first implementation commit, the scenario that covers the spec's headline criterion must exist and fail. Commit it red. Inner work then proceeds per the existing per-slice loop; on a directory-shaped spec the orchestrator's scenarios are the outer loop and each task file's `## Done when` is the inner. This is what puts teeth on the test-first claim the toolkit makes in eight places and enforces in none.

**Consumers.** `agents/flow-verifier.md` currently infers which test backs which criterion (line 20). Give it the declared mapping: for each criterion with a scenario, run the named `by:` and report MET/UNMET against that result; a `by:` that does not exist or will not run is **UNCONFIRMED**, never a guess. Same for `skills/pr/reference/spec.md` and `tests.md` — read the declared proofs rather than re-deriving them. Criteria with no scenario keep today's inference behavior, so partial adoption works.

## Done when
- [ ] A spec with `by: ux-validator` reaches `flow-ux-validator` with the same inputs the 1.15 gate passes today; a spec with a command `by:` runs that command and reports its result.
- [ ] A spec carrying only the legacy `validate:` block behaves identically to before this spec — demonstrated against 1.14's own block shape.
- [ ] A spec with neither block adds no step and emits no message.
- [ ] `NOT APPLICABLE` from the validator still passes cleanly and surfaces the verdict.
- [ ] `implement.md` section 3 states the red-first rule, and a build run against a scratch spec shows the failing scenario as the first commit.
- [ ] `flow-verifier` cites the declared `by:` in its verdict for covered criteria, returns UNCONFIRMED for a `by:` naming a nonexistent command, and still infers for uncovered ones.
- [ ] `skills/pr/reference/spec.md` and `tests.md` cite declared proofs where they exist.
