## Problem
Every artifact in the toolkit has an independent adversary except the one that defines what "correct" means. Code → `flow-verifier`; diffs → `flow-pr-reviewer`; project → `flow-reviewer`; UI → `flow-ux-validator`. The spec gets one human skim under `checkpoint` and, under `auto-build`, nothing — `skills/run/reference/implement.md:15` has the same agent author the spec and then build it. A defective acceptance criterion is therefore delivered faithfully by the implementer, marked MET by the verifier, and passed by PR review: the machinery amplifies the error instead of catching it. `docs/architecture.md:29` ratified a spec agent in the sub-agent catalog; it is the only row in that table never built.

Shipped means: a read-only agent judges a draft spec against a story-quality rubric **before any code is written**, and its verdict lands at the checkpoint the engineer already reads.

## Value
As an engineer running flow I want an independent critique of a spec before I approve it so that a vague or untestable acceptance criterion costs me seconds at plan-time instead of a full implement → verify → review → rebuild cycle.

## Scope
**In:** `agents/flow-spec-reviewer.md` (read-only); a judgment rubric at `skills/run/reference/spec-review.md` built on **INVEST** (spec-level) and **SMART** (criterion-level); dispatch at `implement.md` §2 pre-sign-off and offered on `--add`; autonomy-aware gating; amendment of the stale `architecture.md` Spec-writer row; README/guide/diagram updates.

**Out:** authoring or rewriting specs — the agent never writes, and `add.md` keeps authoring inline (see Decisions). Structural/format checks — owned by `/flow:lint` Step 3 and `flow-spec-guard.sh`; the rubric must not duplicate them. Executable scenarios and AC↔proof traceability — owned by [1.21](../1.21-unified-outcome-declaration-scenarios/1.21-unified-outcome-declaration-scenarios.md). A scope-*amendment* protocol and a producer for `PARTIAL` — neither was in scope here; both remain unwritten backlog candidates.

## Decisions
- 2026-08-17 — **Read-only, not the ratified write-capable Spec-writer.** `agents/flow-verifier.md:25` sets the principle: a judge that patches its own findings is no longer independent. Every judging agent in the toolkit is read-only; a write-capable spec agent would break that separation. The missing piece is the adversary, not the author.
- 2026-08-17 — **INVEST judges the spec; SMART judges each criterion.** INVEST (Independent, Negotiable, Valuable, Estimable, Small, Testable) is a story heuristic and maps onto Value/Scope/sizing. SMART (Specific, Measurable, Achievable, Relevant, Time-bound) is a goal heuristic and maps onto a single AC line. Applying either at the wrong altitude produces noise.
- 2026-08-17 — **Mandatory at `implement.md` §2, optional at `--add`.** §2 is where the stakes are highest and the cost is already amortized, and where `auto-build` has zero spec-side checking today. `--add` is casual idea capture; a forced agent round-trip there would tax the cheapest, most frequent action.
- 2026-08-17 — **Judgment only, never structure.** `/flow:lint` Step 3 and `flow-spec-guard.sh` own shape (sections present, id==stem, no status field). The rubric asks only questions a parser cannot: is this criterion falsifiable, is Scope closed, is this one thin slice, does it collide with a decision already made.

- 2026-08-18 — **AC7 restated to a checkable form at sign-off.** It originally read "raises zero findings that `/flow:lint --specs` already reports, proven by diffing the finding sets" — two prose finding-sets do not diff cleanly, and strict zero overlap in *wording* is unachievable even when the *checks* are properly disjoint. Applying this spec's own SMART lens, Measurable was weak. It now turns on a named list of not-performed checks, provable by inspection.
- 2026-08-18 — **Built inline with an advisory verifier per task, not one implementer per task.** `implement.md` §3 directs a dispatch for "any cross-cutting spec", but all three slices here are serial prompt-markdown edits with no parallelism to gain and no code seam to isolate; worktree isolation would add ceremony and no safety. Recorded as a deliberate deviation rather than taken silently.
