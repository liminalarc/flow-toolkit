## Goal
Add the read-only judge and the rubric it loads, modelled on the two proven patterns: `flow-reviewer` for shape (rubric-driven, prioritized findings, never edits) and `flow-verifier` for output (a structured verdict the orchestrator can gate on deterministically).

`agents/flow-spec-reviewer.md` — `tools: Read, Grep, Glob`. Given: the draft spec (or the §2 plan), the rubric path, the project root, and `specs/archive/` for prior art. Returns:

```
VERDICT: PASS | CONCERNS
INVEST: <letter> — OK | WEAK — <why, citing the section>
CRITERIA:
  - <AC text> — SMART: OK | WEAK — <which letter fails and what would fix it>
PRIOR ART: <archived spec id + the colliding decision, or "none found">
RATIONALE: <one or two lines>
```

`skills/run/reference/spec-review.md` — the rubric. Discover → Review → Report, matching the other `reference/*` rubrics. Two altitudes:

- **INVEST, on the spec** — Independent (does it depend on unfinished work?), Negotiable (does Scope prescribe implementation where it should state outcome?), Valuable (is the Value benefit a user outcome, or a restatement of Problem?), Estimable (is anything unknown enough to be unsizable?), Small (is this one coherent capability, or three?), Testable (does every AC have a proof?).
- **SMART, per acceptance criterion** — Specific (one observable behavior), Measurable (a stated `— <how proven>` that names a real test/command/observation), Achievable (within this spec's scope), Relevant (traces to the Value story), Time-bound (provable at done-time, not "eventually").

Plus prior art: grep `specs/archive/` Decisions for a settled decision this spec contradicts or re-litigates.
