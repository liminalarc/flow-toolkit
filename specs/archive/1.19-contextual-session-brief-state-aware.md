## Problem
`flow-session-brief.sh` ends every brief with the same constant clause (line 57:
"— run /flow:run for the board"), so the only advisory part of the only push
surface never changes: it says "go look at the board" whether a spec is
half-built, a release is untagged, or nothing is in flight. Separately, line 23
exits when there's no `SPECIFICATIONS.md`, so **ado projects get no brief at
all**. Shipped means: the closing clause is a function of repo state, and ado
projects get oriented too.

## Value
As a developer moving between several flow projects, I want the session brief to
name the one thing that matters in this repo right now, so I re-enter without
re-deriving state — and meet a capability at the moment it would help.

## Scope
**In:** a priority ladder in the awk `END` block (one nudge, highest tier wins);
minimal ado orientation read from `.flow/config.yml`; nudge wording that reads as
state + option rather than an instruction; `hooks.test.sh` cases per tier.
**Out:** any network/board query at SessionStart (latency + offline breakage); a
tips/"did you know" rotation (unearned noise — trains the reader to skip the
line); rubric-drift as a tier — `rubric-drift` sha256s every basis file, too
costly for a hook that runs in every project every session; revisit as its own
spec if the cheap tiers prove valuable.

## Acceptance criteria
- [x] Exactly one nudge is printed — highest true tier wins, never a list — proven by a test per tier
- [x] T1: a `DONE` spec with an unresolved deferral → names the spec + that it blocks shipping
- [x] T2: a spec `IN PROGRESS` → names it and that `/flow:run <id>` resumes
- [x] T3: `DONE` specs tagged since the last tag + clean tree → names the count and `/flow:ship`
- [x] T4 (fallback): today's exact line — no regression for the idle case
- [x] ado (`.flow/config.yml`, no index) → one line naming the backend; **zero network calls**
- [x] Non-flow project → no output, exit 0; the fast-exit still precedes all new work
- [x] Nudges read as state + available option, never an imperative — the brief lands in Claude's context and must not read as an instruction to act
- [x] Cost does not scale with backlog size: a 100-DONE index costs no more than a 1-DONE index, and a 1-of-100 deferral backlog costs no more than 1-of-1 (**revised mid-build** — see Decisions)
- [x] `bash hooks/hooks.test.sh` green; CI green

## Decisions
- 2026-08-11 — One nudge, not a list: a brief that suggests three things trains
  the reader to skip it, which costs the tier-1 warning its credibility.
- 2026-08-11 — Rubric drift scoped out at authoring time rather than deferred
  mid-build: it is the one tier with a real per-session cost (sha256 over every
  basis file), so the decision belongs in Scope, not in `deferrals:`.
- 2026-08-11 — **Perf AC revised mid-build.** The original "< 300ms on a
  100-DONE repo" was unachievable and measured the wrong thing: the unmodified
  script already cost ~400ms/run under Git Bash, where each subprocess is
  ~100ms, and runtime was identical for a 1-spec and a 100-spec index. Replaced
  with two assertions that are actually ours — no scaling with backlog size,
  plus a gross-regression ceiling.
- 2026-08-11 — **T1 kept despite its cost** (user decision). Narrowed, it adds
  ~1s to session start on a repo carrying deferrals (3.6s → 1.4s measured
  here); the alternative was re-homing it until the helper itself is faster.
  The underlying cost is `flow-preflight.sh resolved`, which the commit guard
  also pays on every commit — a candidate for its own spec.
- 2026-08-11 — T1 narrows the helper's input rather than re-implementing the
  rule: one grep finds specs carrying a `deferrals:` key, ids are read with
  shell builtins, and only the intersection with the index's DONE set is
  passed via `--done`. The rule stays single-source in `flow-preflight.sh`.

## Verification / evidence
- Tiers + precedence, ado, fast-exit: `hooks/hooks.test.sh` — 134 pass, each
  tier asserting both its own text and the absence of the tier below it.
- No backlog scaling: 100-DONE vs 1-DONE index, and 1-of-100 vs 1-of-1
  deferral backlog, compared over 10 runs each.
- End-to-end on this repo: prints `… is IN PROGRESS · 18 DONE — /flow:run 1.19
  resumes it`; 10 runs in 14s (1.4s each, down from 3.6s pre-narrowing).
- The fixtures initially passed while the real repo cost 3.6s/run — the
  regression only appeared under `grep -rl` finding real `deferrals:` files,
  which is why the end-to-end smoke test is a done-gate and not optional.
