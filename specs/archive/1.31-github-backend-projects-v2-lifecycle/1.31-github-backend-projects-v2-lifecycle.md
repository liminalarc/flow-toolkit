## Problem
flow had two lifecycle authorities, `local` and `ado`. `liminalarc/atlas` tracks work on the org
Projects v2 board `liminalarc/projects/36`, which flow could neither read nor write: no way to
configure it, no index for `/flow:run`, and every ado-only path (archival trigger, pointer comment,
cross-repo tags, lint reconciliation, ship's DONE resolution) without a github counterpart.
`commands/init.md` already named `github-issues` as the next adapter. Shipped = a repo whose
backlog is board 36 runs the full loop with no local index.

## Value
As an engineer whose team tracks work on a GitHub Projects board, I want flow to treat that board
as the index so that I get the same spec-driven loop — and the same DONE gates — without
maintaining a second backlog.

## Scope
**In:** `lifecycle_authority: github`; config + `/flow:init --backend github` with column discovery;
the `gh` ladder incl. the `project` scope gap; the Status field as `state_map`; repo-qualified ids;
the run path (board read, Status write, `Spec:` comment, terminal-column archival, `--add`);
cross-repo `repo:`/`slice-done:` labels; session-brief orientation; `/flow:lint` reconciliation +
drift; `/flow:ship` DONE resolution; a programmable `gh` stub; the board 36 walk; docs + ADR.
**Out:** labels as a *status* carrier; any board write beyond the Status field, one comment, the
cross-repo labels and item creation; an MCP rung; jira; behavior changes to `local`/`ado` beyond
generalizing shared prose.
**Precondition:** the `gh` token carries `project` scope before T1. An org policy refusing the grant
blocks this spec and is surfaced, never worked around.

## Decisions
- 2026-11-18 — `lifecycle_authority: github`; `github-issues` in prose, per `commands/init.md`.
- 2026-11-18 — **Status field, not labels.** The columns are what the team moves; a parallel
  `status:*` set would drift and duplicate a state the board owns. Labels keep one job: the
  cross-repo `repo:`/`slice-done:` tags, which Projects v2 has no field for — and the 1.29
  resolvers take tags as input, so no hook gains a query.
- 2026-11-18 — **Ids always repo-qualified** `<repo>-<n>`. Issue numbers are unique per repo only
  and an org board can gain one anytime, so qualifying unconditionally means no id ever changes.
  Parsed as *last dash-delimited numeric segment*, applied to `id:`, never to a filename (1.17).
- 2026-11-18 — **`gh`-only ladder.** The first draft's "announced MCP fallback" named no server, and
  an unnamed rung cannot be tested. A failure, a missing `project` scope, or no `gh` stops and
  reports — an unreadable board is never an empty backlog.
- 2026-11-18 — **Board 36, read.** Columns are `Discovery · Backlog · Ready for Dev · In Dev ·
  Dev Done · Ready for Review · Deployed` — nothing like GitHub's defaults, retiring the
  "hardcoded map passes vacuously" risk here. 17 items, all `liminalarc/atlas`. `state_map` mirrors
  ado's categories: pre-dev → `NOT STARTED`, in flight → `IN PROGRESS` (as ado maps `Resolved`),
  `Deployed` → `DONE`, closed `not_planned` → `SUPERSEDED`.
- 2026-11-18 — **Three `gh` facts, checked on 2.103.3** (pinned because a later review round
  disputed the first from recall and was wrong): `item-edit` selects by issue `--url` and permits
  one field per invocation; `item-list` defaults to `--limit 30`, so an unscoped listing truncates;
  `issue comment --edit-last` edits the user's last comment *whatever it is*, so the pointer must be
  found by its `Spec:` marker. Confirmed live.
- 2026-11-18 — **The stub is programmable, unlike 1.27's `az` double** ("exits 0 and prints
  nothing"). Nine criteria need it to *answer* — canned options, a scope error, item lists, comment
  lists — and a write is only reached after a read resolves the item. It stays a fixture.
- 2026-11-18 — **One spec, nothing deferred.** Two review rounds called INVEST-Small WEAK; round 1's
  seam was withdrawn by its own author, round 3's rested on the spec pre-naming T4 as deferrable.
  That basis was removed rather than argued: all six tasks landed. Round 2's "ado's base backend was
  one spec" precedent was **not** used — nothing in the archive (1.1-1.30) introduces ado, so it is
  unverifiable here.
- 2026-11-18 — **Backend branching, measured not assumed.** `lifecycle_authority` appears in exactly
  one hook (the session brief); `flow-preflight.sh` reads only `repo_name`/`related_repos`; the
  guards read no config. A third backend is free at the hook layer — that is what the
  `--done`/`--tags`/`--slice-done` input design (1.27, 1.29) bought.
- 2026-11-18 — **The terminal column closes the issue.** `Deployed` flipped #51 and #54 to
  `CLOSED`/`COMPLETED` with one `item-edit` and no close call; `In Dev` did not. Flow's boundary
  held (every other field byte-identical), but "flow never closes an item" is wrong about *effects*,
  so the terminal proposal must disclose it. Closed+`COMPLETED` maps to `DONE`; archival unchanged.
- 2026-11-18 — **Teardown: board item first, then the issue.** `item-delete` succeeds on an item
  that still has content; it is denied on an already-orphaned row. Reversing the order strands a
  null-content row until GitHub reaps it, and you cannot then close that window.
- 2026-11-18 — **Verification apparatus traps, both found the hard way.** A Windows-form `PATH`
  entry is ignored by Git Bash, so a run silently graded the **live board** and "passed" — every
  run now asserts `which gh` resolves inside `gh-stub`. And a fixture that answers only some
  subcommands lets the rest fall through to exit 0 + empty stdout, which reads as an empty board;
  emptiness is decided from **exit status**, never from empty output.
- 2026-11-18 — Further live facts: `item-add` lands an item in the board's **default** column, so
  `--add` must not assume a single `NOT STARTED` target (board 36 has three); `item-list` **lags its
  own writes**, so a just-added item missing from a listing is not a failed add; `gh api` endpoints
  take **no leading slash** (Git Bash rewrites `/repos/...` into a path), and the pointer refresh is
  `gh api --method PATCH repos/<o>/<r>/issues/comments/<id>` — gh has no edit-comment-by-id command.
- 2026-11-18 — The root CLAUDE.md line cap is not an AC: `flow-claude-guard.sh` owns it.

## Verification / evidence
All 27 criteria proven; `hooks.test.sh` **322 passed / 0 failed**, `docs/mermaid.test.sh` **6/6**.

- **Hook-level (CI-replayable):** ids in flat/dir/archive form, the session-brief line + shadowed
  key + missing `project_number` + non-github fall-through + a poisoned `gh` on `PATH`, and an
  integrity case per stub fixture.
- **Stub-driven prompt paths:** init writes the config / creates `specs/` / writes no index;
  `state_map` keys equal the three *invented* option names (`Icebox`/`Cooking`/`Shipped`), so a
  call-then-ignore or hardcoded implementation fails; the scope gap stops init with nothing
  written; every mapped column resolves, `Parking Lot` reports `unmapped`, closed `not_planned`
  resolves `SUPERSEDED`; 8/8 items grouped with none ungrouped; the empty board answers cleanly;
  45 of 45 returned with an explicit `--limit`; authoring produces `atlas-12-add-user-login.md`
  that the guard accepts; `--add` issues one create + one item-add + one item-edit; the done-step
  issues exactly one `item-edit`, one comment PATCH and one `slice-done:` add, all on the
  designated item, with no close/assign/milestone/delete; no `mcp__` board path exists; a failing
  `gh` is non-zero with no payload and an absent `gh` exits 127; label-derived tags drive
  `resolve-footprint`/`slice-status`; a terminal-column issue with an active detail is flagged with
  nothing moved; an unreachable board is non-zero; `--fix` performs both the `repo:` add and remove
  while never touching `slice-done:`; ship blocks on an open deferral (exit 2) and on a non-`done`
  slice.
- **Live on board 36 (issue #54, torn down):** `In Dev` → `Deployed`, detail archived with filename
  unchanged, exactly one pointer comment resolving to the archived path, board restored to 17 items
  / 0 orphans / 9-6-2 with no trace of the issue.
- **Cold-reader docs test:** a fresh agent given only the five docs produced a correct
  `.flow/config.yml` for board 36. Its first run **failed** — no schema or example existed — which
  is what drove the §2.3 config block, the token-vocabulary statement and the contradiction fixes.

Two apparatus defects are recorded rather than hidden: a Windows-form `PATH` made one run grade the
live board instead of the stub, and a gap in the `scope-error` fixture let an unreachable board look
like an empty one. Both now have guards.
