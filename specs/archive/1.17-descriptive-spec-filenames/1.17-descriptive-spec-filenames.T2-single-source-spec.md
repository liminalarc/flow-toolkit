## Goal
Today id→path resolution is duplicated: `to_resolves` (`flow-preflight.sh:143-146`) and
`cmd_resolved` (`:182-185`) each hardcode the same four lookups. A slug turns each into a
glob, so per root `CLAUDE.md` ("a machine-checkable rule lives in exactly one place") add
one subcommand and make both call it:

`flow-preflight.sh spec-path <id> [--repo DIR] [--spec-dir specs]` → prints the resolved
path, exit 0. Search order, first hit wins: flat `<id>.md`, dir `<id>/<id>.md`, then the
slugged equivalents `<id>-*.md` / `<id>-*/<id>-*.md`, each in the active dir then
`archive/`. Exit 1 = no such spec (silent — callers decide if that's an error). Exit 2 =
**ambiguous**: two slugged files for one id, which is a real authoring bug worth naming.

Also fix a latent bug in the same code: `cmd_resolved`'s DONE-id grep (`:171`) requires a
dotted id (`[A-Za-z0-9]*[.][A-Za-z0-9-]+`), so ado's flat ids (`642103`) never match and
the deferral `DONE`-gate is silently inert in ado mode. Widen it to the guard's own id
pattern (`[A-Za-z0-9][A-Za-z0-9.-]*`).
