## Goal
Generalize `skills/run/SKILL.md` + `reference/implement.md` from "local or ado" to a backend-neutral
shape with a github column, so each rule keeps one definition. The write boundary is ado's,
transposed: Status single-select, one pointer comment, cross-repo labels, nothing else.

## Done when
- [ ] `/flow:run` (no args) lists board 36's **open** items grouped by mapped column; an empty result
      says the query ran rather than implying an empty backlog (stub-asserted).
- [ ] `/flow:run <repo>-<n>` resolves the issue, authors `specs/<repo>-<n>-<slug>.md` with the slug
      from the issue title, and writes no status into the detail file — spec guard passes.
- [ ] Status resolution is implemented to the three documented cases: mapped column → token, closed
      `not_planned` → `SUPERSEDED`, no/unmapped column → the literal `unmapped` report with no token.
- [ ] Sign-off sets the Status single-select to the IN PROGRESS column (propose-only, confirm-first);
      the done-step proposes the terminal column and archives on a terminal-category mapping.
- [ ] Setting Status selects the item by its issue `--url` and the field by `--field Status --value
      <column>` (the documented path; a GraphQL item id is optional) — the capture log shows exactly
      one `item-edit` call. The CLI permits one field value per invocation on a non-draft issue, so
      that guarantee is relied on, not re-implemented.
- [ ] The board listing carries an explicit `--limit` or a `--query` scope, because
      `gh project item-list` defaults to 30 items and would silently truncate a real board.
- [ ] One `Spec: <path> @ <sha>` comment is refreshed, never duplicated, with the path from
      `flow-preflight.sh spec-path`, written after archiving so it points at the final home. It is
      located by its `Spec:` marker through `gh issue view --json comments`; `--edit-last` alone is
      forbidden, since it would overwrite a human comment posted after flow's.
- [ ] `--add` drafts the issue, confirms, creates it, adds it to the board, sets the initial column
      and adopts the returned `<repo>-<n>` as the id. It carries **no** verification-mode branch —
      flow has no such mode, and a conditional `flow-test` label would either be unimplementable or
      label every production issue. Verification exercises `--add` against a scratch project.
- [ ] Cross-repo: `repo:`/`slice-done:` labels are read from the issue and passed to
      `resolve-footprint`/`slice-status` as `--tags`/`--slice-done`; `slice-done:<repo>` is added as
      exactly one label at the done-step, with no other field write.
- [ ] **No preflight subcommand gains a `gh` call** — grep-provable, and the outcome that actually
      matters per `hooks/CLAUDE.md`'s "board data is an input, never a query". (Stated this way
      because "the diff is empty *or* a change lands with a test" is satisfied by either outcome and
      so proves nothing.)
- [ ] A `gh` failure anywhere on this path is announced and stops the run; no silent no-op.
