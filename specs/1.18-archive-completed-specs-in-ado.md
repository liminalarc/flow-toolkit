## Problem
In ado mode a finished spec's detail file never moves. The done-step's archive step is gated
`**Archive** (local)` (`skills/run/reference/implement.md:52`), so an ADO-backed repo
accumulates every closed story in the active `specs/` folder forever until browsing it is
useless — the one problem archiving exists to solve. `commands/init.md` makes it worse: the
Feature Completion Checklist it generates for **new ado projects** says "update the index
status + archive the detail file" (`:99`, and `:191` repeats it unqualified), so flow hands
each ado project an instruction its own done-step will never carry out. Cards also close on
the board outside flow — a teammate closing one in the ADO UI leaves its file behind with
nothing watching. Shipped = a closed card's detail file lands in `<spec_dir>/archive/` in ado
just as it does in local, including cards flow didn't close itself.

## Value
As an engineer on an ADO-backed repo, I want a closed story's spec file to move out of the
active folder, so browsing `specs/` shows me live work instead of years of finished stories.

## Scope
**In:** un-gate the done-step's archive move for ado (driven by the card reaching a
Closed-category state via `state_map`); a `/flow:lint` reconciliation sweep for cards closed
outside flow; fix `init.md`'s contradictory checklist; docs.
**Out:** renaming `archive/` or adding a `completed/` folder — the terminal status is already
single-source in the index/board, and a second folder would duplicate it (see Decisions);
retro-moving anything in an existing repo; sub-grouping archived specs by date or iteration;
any hook change (`spec-path` and `resolved` already resolve `archive/`).

## Acceptance criteria
- [ ] ado done-step moves the detail to `<spec_dir>/archive/` after the card transition —
      filename unchanged, a whole directory moved together — proven on a scratch ado repo
- [ ] The move follows the card reaching a **Closed-category** state per `state_map`, not a
      hardcoded state name
- [ ] `SUPERSEDED` (Removed-category) archives by the same path — no separate handling
- [ ] `/flow:lint` in ado reports any Closed-category card whose detail is still in the active
      folder and offers the move **confirm-first**; never moves unprompted
- [ ] That sweep is MCP-first with an `az boards` fallback, and **announces** the fallback or
      stops — never a silent no-op on an unavailable board
- [ ] `/flow:lint` emits nothing for local repos (the sweep is ado-only) and nothing for a
      spec already archived — no new noise
- [ ] `init.md`'s generated checklist (`:99`) and `:191` describe archiving accurately for both
      backends — no promise ado won't keep
- [ ] `docs/guide.md` §2.3 states that archival now behaves identically in both modes; README
      + `docs/how-it-works.md` no longer imply archival is local-only

## Decisions
- 2026-07-30 — One `archive/` folder for both terminal outcomes. Splitting `completed/` from
  `archive/` was considered and rejected: the outcome (`DONE` vs `SUPERSEDED`) is already
  single-source in the index/board, so encoding it in the folder path would be a second
  source of truth to drift. "Archive" = closed out, no longer active; outcome lives elsewhere.
- 2026-07-30 — Routing is driven by `state_map`'s state **category**, so the rule stays
  backend-neutral and survives a team renaming its board states.
- 2026-07-30 — Reconciliation is a `/flow:lint` sweep, not a hook: it needs a board query,
  and hooks must stay zero-cost and offline in unrelated projects.
- 2026-07-30 — No hook or `hooks.test.sh` change; `spec-path`/`resolved` already resolve
  `archive/`. Verification is exercising the commands on a scratch ado repo.

## Verification / evidence
A scratch repo with an `ado` `.flow/config.yml`: run the done-step against a card transitioned
to Closed and confirm the file moved with its name intact; close a second card directly on the
board and confirm `/flow:lint` reports it and moves it only on confirmation; run `/flow:lint`
in this (local) repo and confirm zero new findings.
