## Problem
With the footprint declared (1.25) and resolvable (1.29), nothing yet says it out loud. A run still opens silently on one slice of a multi-repo item, and the human is the only thing that remembers the other repos exist. This is the half of the design that aids the orchestrator: say what the item spans, say which slice this run builds, say what remains.

Shipped means: starting and finishing a cross-repo slice tells you the full footprint and what is still outstanding.

## Value
As an engineer starting a run I want the item's full footprint announced up front so that I am told what remains before I merge, rather than discovering it after.

## Scope
**In:** presentation only. A `/flow:run` start banner, and a done-step reminder, both rendered from what `flow-preflight.sh resolve-footprint` and `slice-status` return (**owned by 1.29**; this spec calls them and never re-derives either answer). The banner names the footprint, which slice this run builds, each sibling's handle and expected slice location, its `clone` string as copy-paste text, and — when the resolver reports one — a divergence line. **Every one of those data items comes from 1.29's `resolve-footprint` record**; this spec reads no config and composes no path. The reminder lists the siblings not yet `done`, rendering 1.29's four-way vocabulary rather than inventing its own. On the **ado path** the card's `repo:` tags are passed into `resolve-footprint --tags` from the card data `/flow:run` §1 already reads — the skill queries the board because it always has; the hook never does, per 1.29. Insertion points: `skills/run/reference/implement.md` §1 (banner) and §4 (reminder), plus one Rules line in `skills/run/SKILL.md`.

**Out:** resolving anything — footprint source, tag parsing, divergence detection, and sibling status all belong to 1.29. Rendering `undeclared:`/`undeclared-self:` or acting on them — 1.28 does the asking; this spec ignores those lines. Blocking: every message here is advisory; the gate is 1.27. Fetching `clone`. Writing to a sibling. Writing the tag mirror or repairing drift (1.28). Session-brief integration.

## Acceptance criteria
- [ ] The banner contains all five promised elements against a two-repo fixture — the footprint, this run's slice, each sibling's handle, its expected slice path, and its `clone` string verbatim — proven by a checklist against the captured banner text.
- [ ] The banner renders `clone:` straight from the resolver line and never fetches it — proven by inspection of the added §1 text containing no fetch/`ls-remote`/`az` instruction, resting on 1.29's shipped grep proof that the resolver itself has no network call on any path. (A `PATH` stub is not available: `/flow:run` is a model-executed prompt whose session PATH the harness does not control.)
- [ ] The banner fires when a `repo:` line's name differs from the `this:` line, **or** when `this:` is absent while `repo:` lines exist (a project that never declared `flow.repo_name` — the resolver emits `undeclared-self:` instead, and the footprint still spans repos) — proven by inspection of the stated fire condition in `implement.md` §1, plus two scratch runs: a single-repo spec producing no banner, and a `repo_name`-less config still producing one.
- [ ] It names every sibling on a >2-repo footprint, not just the first — proven by a scratch run on a three-repo fixture.
- [ ] In ado mode, a card whose footprint resolves from tags banners in a repo with **no** local slice file and names the **directory the slice would land in** (the resolver's `slice:` value — the filename is unpredictable by design, per 1.24 D2) — proven by a scratch run whose card tags are passed into `--tags` from read card data, not a live board query.
- [ ] When the resolver reports a divergence, the banner prints one line naming the repos the tags add or omit, uses the front-matter set, and the run proceeds — proven by a scratch run on a fixture whose tags name a third repo the front-matter omits.
- [ ] Each sibling's line renders 1.29's four-way value verbatim on the flat-file path — `done`, `open`, `absent`, `cannot-determine` — with no fifth vocabulary of its own, **and carries the parenthesised reason the resolver supplies** for `absent`/`cannot-determine` — proven by four scratch runs, one per value, asserting both token and reason. The reason is what makes `cannot-determine` actionable; dropping it is the silent-pass this spec's own Decision forbids. (The ado branch returns only `done`/`open`, so the four-value assertion is flat-file only.)
- [ ] The run performs no write to the sibling — proven by asserting the sibling tree's `git status` is unchanged afterwards.
- [ ] The done-step reminder lists every sibling that is not `done`, marking `absent` and `cannot-determine` ones as such rather than omitting them, and is silent only when all siblings report `done` — proven by four scratch runs: all-done, one-open, one-absent, one-unreachable.
- [ ] The reminder is a **top-level §4 bullet placed immediately after Restart & smoke-test and before the Validation gate bullet** — proven by inspection of the bullet order. One anchor, not two: "before `Status →`" alone would permit nesting it inside the Validation-gate bullet, which is a pure no-op for any spec without a `validate:` block, so it would silently never fire for most specs.
- [ ] Every documentation surface is updated in the same change — proven **per anchor**, not per file: the banner token appears under `docs/guide.md` §3's `/flow:run` entry **and** a named two-repo walkthrough heading exists under §6 (a deliverable 1.24's owner table assigns to this spec), plus `README.md` §The development cycle, `docs/how-it-works.md` §1's diagram, and one Rules line in `skills/run/SKILL.md`. A per-file `grep -l` would pass with §6 missing entirely.
- [ ] `bash docs/mermaid.test.sh` is green after the §1 diagram edit, with any node label containing `[`, `]`, `(`, `)` or `{`, `}` quoted per CLAUDE.md — proven by running it.

## Decisions
- 2026-09-24 — **Advisory only; the gate is 1.27.** A reminder that blocks is a gate with a worse error message. Separating them keeps this slice shippable alone and keeps the blocking decision in one place.
- 2026-09-24 — **Presentation only; 1.29 owns every answer.** The first draft resolved the footprint and read sibling status in prompt prose while declaring "no hook logic changes here" — which left both with no legal home, duplicated 1.27's and 1.28's work, and (since 1.27 is ordered after this) guaranteed that a prose reader would be rewritten in bash. This spec now renders; it does not derive.
- 2026-09-24 — **`cannot-determine` is shown, never hidden.** Omitting an unverifiable sibling from the reminder would read as "nothing outstanding" — the silent pass 1.27 forbids one step later.

## Verification / evidence
Scratch runs against purpose-built fixtures: a two-repo footprint, a three-repo footprint, one with a readable `local_path` sibling, one with it removed, and one whose card tags diverge from front-matter. The ado path feeds 1.29's `--tags` flag, so nothing here needs a live board. `bash hooks/hooks.test.sh` must stay green — no hook logic changes in this spec.

**Coordination, not dependency:** in-flight 1.23 edits `skills/run/reference/implement.md` §3 and `SKILL.md`'s Rules — the same two files this spec touches at §1/§4 and Rules. Intended order: whichever reaches build first lands, the other rebases.
